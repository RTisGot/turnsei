# 推奨コード読解順序

1. `Scene.h / Scene.cpp`：ゲーム全体の状態機械
2. `Title.cpp`：開始地点
3. `StoryEvent.cpp`：データ駆動会話とFieldへの遷移
4. `Field.cpp`：探索ループ、章進行、エンカウント
5. `Player.cpp / FieldEnemy.cpp`：移動と敵AI
6. `SimpleMap.cpp`：街描画、路面、実メッシュ衝突
7. `CombatSystem.h / CombatSystem.cpp`：戦闘ルールとターン状態
8. `CombatSystemRender.cpp`：戦闘描画、HUD、モーション同期
9. `ImportedModel.h / ImportedModel.cpp`：3Dデータ、材質、骨、アニメーション
10. `ActorRenderer.cpp`：フィールド用PBR・スタイライズGLSL
11. `author_combat_animations.py`：待機・攻撃の姿勢生成
12. `export_character_gameplay.py`：ウェイト修正とゲーム用出力
13. その他のBlender生成スクリプト：水没都市制作パイプライン

## 重要な設計境界

- `CombatSystem.cpp`は戦闘ルール、`CombatSystemRender.cpp`は表示と入力を担当する。
- `ImportedModel`はモデル資産の読み込みと再生を担当し、ゲームルールを知らない。
- `SimpleMap`は見た目と衝突の座標系を一致させる。
- Blenderスクリプトは制作時の変換を担当し、実行時コードへDCC固有処理を持ち込まない。
- JSONアニメーションは、Blenderバージョン差によるFBX Action Slot変換失敗を避けるための明示的な中間形式である。
